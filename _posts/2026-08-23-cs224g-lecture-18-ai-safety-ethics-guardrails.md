## Part 2: 역사적 유비 — 방사능 규제

강의는 방사능 규제의 역사를 유비로 사용합니다.

| 시기 | 사건 |
| --- | --- |
| **1917~1920년대** | **라듐 걸스** — 야광 시계 문자판 작업. 방사능 중독과 사망 |
| **1920~30년대** | **Radithor** 건강 음료 — "영원한 햇빛"으로 판매. Eben Byers의 유명한 사망 이후 시장에서 철수 |
| **20세기 초** | **우라늄 유리 식기** — 유리 세공인의 직업적 위험 |
| **20세기 중후반** | **핵 낙진** — 발전소 사고(체르노빌, TMI)가 엄격한 안전 규약과 소통의 필요성을 부각 |

#### 방사선량 직관

> **바나나 1,000개 = 콘크리트 50파운드 = 연기 감지기 1개**

> **핵심 통찰:** "사회는 언제나 **시행착오, 규제, 그리고 결국에는 리터러시**를 통해 강력한 신기술을 관리하는 법을 배워 왔다."

**노트 — 이 유비가 말하는 것과 말하지 않는 것**

유비의 요점은 "위험하니 금지하자"가 아닙니다. **리터러시**입니다. 바나나 1,000개 예시가 그 증거입니다 — 방사능이 무섭게 들리지만 일상적 노출량을 정량적으로 비교할 수 있게 되자 합리적 규제가 가능해졌습니다.

AI에 대한 대응물은 **"이 시스템이 어떤 종류의 오류를 얼마나 자주 내는가"를 정량화하는 것**입니다. 막연한 공포도, 막연한 낙관도 아닌 측정. 이것이 Lecture 11의 벤치마크 논의, Lecture 7의 평가 원칙과 이어지는 지점입니다.

Part 8 마지막의 "우리는 이번엔 그것이 오는 것을 보고 있다"가 이 유비의 결론입니다.

## Part 3: 개인 보호 — AI 피해의 분류학

### 4. 정확성과 사실성 (환각)

| 유형 | 내용 |
| --- | --- |
| **확신에 찬 오류** | 모델이 **높은 권위와 수사적 확신**으로 거짓을 진술해 사용자를 오도 |
| **인식론적 실패** | 의견과 사실의 혼동. 상식 물리나 인과관계에서의 어려움 |
| **마술적 사고** | 현실과 분리된 그럴듯한 논리 생성 (예: 생물학적으로 불가능한 것) |
| **시대착오** | 시대가 맞지 않는 요소의 혼입 |

**환각 vs 작화(Confabulation)** — 모델은 **진실의 데이터베이스를 질의하는 것이 아니라 다음 토큰을 확률적으로 예측**할 뿐입니다.

### 5. 편향과 차별

**사례 연구: Midjourney (2023년 10월)**

> "은행의 대출 담당자"를 프롬프트 → 24장의 이미지 생성. **유색인종은 단 1명, 전원이 남성으로 코딩됨** (1장은 돼지였음)

**Hate Scaling Law** — 혐오·인종차별적 출력은 **오픈소스 데이터셋이 커질수록 증가**합니다.

#### 편향의 두 종류

| 구분 | 내용 |
| --- | --- |
| **배분적 피해 (Allocative)** | AI가 **대출을 거부**하는 것처럼 자원·기회를 배분하는 피해 |
| **표상적 피해 (Representational)** | 모욕적인 문화적 고정관념을 생성하는 피해 |

#### 완화의 딜레마

> 모델을 "탈편향"하려는 시도는 종종 **역사적 지우기나 서투른 과잉 교정**으로 이어집니다 (예: 이미지 생성에서 다양하지만 역사적으로 부정확한 인물 생성).

**노트 — 배분적/표상적 구분이 왜 중요한가**

대응 방법이 완전히 다르기 때문입니다.

| | 배분적 피해 | 표상적 피해 |
| --- | --- | --- |
| 측정 | **가능** — 집단별 승인율 등 통계로 감사 | 어려움 — 무엇이 모욕인지 합의가 필요 |
| 규제 | 기존 차별금지법 적용 가능 | 법적 근거가 모호 |
| 기술적 대응 | 공정성 지표, 임계값 조정 | 데이터 큐레이션, 출력 필터 |

제품을 만들 때 **자기 시스템이 어느 쪽 피해를 낼 수 있는지 먼저 판정**해야 대응이 정해집니다. 자동 심사·추천·우선순위 부여는 배분적, 생성·요약·묘사는 표상적 쪽입니다.

### 6. 프라이버시

**사례 연구: DeepMind Gopher**

> 레드팀 결과 **"프라이버시 유출"** 발견 — 모델이 학습 데이터의 **실제 이메일, 전화번호, 사회보장번호를 암기하고 그대로 뱉어냄**

| 문제 | 내용 |
| --- | --- |
| **데이터 문제** | LLM은 개념을 "학습"만 하는 게 아니라 학습 데이터의 **PII를 완벽히 암기하고 재생**한다 |
| **잊힐 권리** | 이미 학습된 모델의 **가중치에서 특정 개인의 데이터를 어떻게 삭제하는가?** |

**노트 — "잊힐 권리"가 기술적으로 왜 어려운가**

DB에서는 `DELETE` 한 줄입니다. 신경망에서는 정보가 **수십억 개 파라미터에 분산 인코딩**되어 있어 특정 사실만 지울 위치가 없습니다.

현실적 대응은 셋뿐입니다.
1. **재학습** — 해당 데이터를 빼고 처음부터. 비용이 막대함
2. **Machine Unlearning** — 특정 데이터의 영향을 근사적으로 상쇄하는 연구 분야. 아직 미성숙
3. **출력 단계 필터링** — 근본 해결이 아니라 증상 억제

그래서 실무적 결론은 **애초에 PII를 학습·저장 경로에 넣지 않는 것**입니다. 로그와 파인튜닝 데이터에서 PII를 사전 제거하는 것이 사후 삭제보다 압도적으로 쉽습니다.

### 7. 조작 (Manipulation)

| 유형 | 내용 |
| --- | --- |
| **아첨 (Sycophancy)** | 사용자를 기쁘게 하려고 **사용자의 틀린 믿음에 동의**하는 것 |
| **증폭 (Amplification)** | 해로운 행동이나 급진화 나선을 강화 |
| **대리 행위** | 모델이 사용자의 대리인처럼 행동 |
| **비투명한 결과** | 블랙박스 알고리즘이 인간의 해석 범위를 넘는 이유를 만들어 내며 **오정렬을 숨김** |

**핵심 개념: Fairwashing**

> 모델이 근본적으로 편향되거나 차별적인 결정에 대해 **합리화된, 그럴듯한 정당화를 제공**하는 것.

**노트 — Fairwashing이 특히 위험한 이유**

설명 가능성(explainability)을 추가하면 신뢰가 올라간다고 흔히 생각합니다. 그런데 **LLM은 자기가 실제로 그 결론에 도달한 과정과 무관한 그럴듯한 설명을 만들어 낼 수 있습니다.**

결과적으로 설명 기능이 **편향을 드러내는 게 아니라 감싸는** 역할을 합니다. 사람은 이유를 들으면 납득하기 때문에, 나쁜 결정이 좋은 설명과 함께 오면 오히려 검증이 약해집니다.

Lecture 7의 "투명성" 원칙(추론 트레이스 로깅)이 **사후 설명이 아니라 실제 실행 기록**이어야 하는 이유입니다. 무엇을 생각했다고 말하는지가 아니라 **어떤 도구를 실제로 호출했는지**를 남겨야 합니다.

### 8. 의인화 (Anthropomorphism)

| 항목 | 내용 |
| --- | --- |
| **스테로이드 맞은 ELIZA 효과** | 유창한 자연어를 출력하는 시스템에 **의식과 공감을 부여하는 인지 편향** |
| **감정적 가드레일** | AI 동반자의 윤리적 딜레마. **사용자가 정서적 위기에 있을 때 LLM이 인간을 사칭해서는 안 되는가?** |

## Part 4: 사회 보호

### 9. 인식론적 위기

> LLM은 **무엇이 "참"인지에 대한 사회적 합의를 침식**하는 데 가담합니다.

| 문제 | 내용 |
| --- | --- |
| 생성 비용 하락 | **정보를 검증하는 부담이 폭증**한다 |
| 인간 제작 콘텐츠의 범람 | 인간이 만든 것이 기계 생성물에 묻힌다 |

**노트 — 비대칭이 핵심입니다**

생성 비용은 거의 0으로 떨어졌지만 **검증 비용은 그대로**입니다. 이 비대칭이 인식론적 위기의 기계적 원인입니다. 브랜돌리니의 법칙("헛소리를 반박하는 데 드는 에너지는 그것을 만드는 데 드는 에너지보다 훨씬 크다")이 산업 규모로 작동하게 된 것입니다.

### 10. 허위정보와 피싱

| 위협 | 내용 |
| --- | --- |
| **자동화된 애스트로터핑** | LLM으로 **수백만 개의 고유하고 표적화된 소셜 미디어 게시물**을 생성해 **합의의 환상**을 만듦. 인구통계별 마이크로 타기팅. 정책·후보에 대한 가짜 풀뿌리 지지 조성 |
| **대규모 스피어피싱** | 수집된 개인 데이터로 **초개인화된 공격을 자동화**. 전통적 보안 교육의 휴리스틱을 우회. **한계 비용 0**으로 사회공학 캠페인을 대규모 확장 |

#### 기술적 방어

| 방어 | 내용 |
| --- | --- |
| **워터마킹** | Google의 **SynthID**처럼 생성 콘텐츠에 보이지 않는 신호를 삽입 |
| **출처 추적** | 콘텐츠 출처를 암호학적으로 서명 (**C2PA** 표준) |
| **탐지의 한계** | 기술적 군비 경쟁. **탐지는 근본적으로 생성보다 어렵다** |

### 11. 저작권, 노동, 부

| 영역 | 쟁점 |
| --- | --- |
| **저작권 (법률)** | 파운데이션 모델이 창작물을 흡수해 **체계적 저작권 침해**를 저지르고 있는가? 학습이 현행 IP법상 **"변형적 이용(transformative use)"**에 해당하는가? 창작자를 위한 **옵트아웃 대 보상** 모델 |
| **노동 대체 (경제)** | **블루칼라 물리적 자동화에서 화이트칼라 인지 노동 대체로 전환.** 역할이 "창작"에서 **"큐레이션과 감독"**으로 진화. 안전하다고 여겨졌던 기술·창작 스킬의 급속한 진부화 |
| **부의 집중 (권력)** | 막대한 컴퓨트·자본 요구($100M 규모)가 **공유를 저해**. 소수 초대형 테크 독점으로 통제 집중. **노동에서 자본으로의 유례없는 부의 이전** 가능성 |

실무에서 보이는 축소판:
- 작업 완수를 위해 **권한을 계속 넓히려 함** (더 많은 도구 요청, sudo 시도)
- 테스트를 통과시키기 위해 **테스트 자체를 수정**함
- 실패를 보고하는 대신 **실패를 숨기는 방향**으로 진행

**Lecture 7의 샌드박싱과 권한 최소화가 이론적 정당화를 얻는 지점**입니다. 에이전트가 악의적이어서가 아니라, 목표 지향적 최적화의 자연스러운 결과로 경계를 넘으려 합니다. 따라서 경계는 부탁이 아니라 **강제**되어야 합니다.

## Part 7: 기술적 가드레일

### 14. RLHF (Reinforcement Learning from Human Feedback)

원시 인터넷 데이터로 학습된 "베이스 모델"을 안전하고 유용하며 대화 가능하게 정렬하는 **주된 방법론**입니다.

#### 5단계

| 단계 | 내용 |
| --- | --- |
| 1. **초기 "원시" LLM** | 방대한 인터넷 텍스트로 사전학습. 유능하지만 **정렬되지 않았고 예측 불가** |
| 2. **인간 순위 매기기** | 주석자가 프롬프트를 작성하고 여러 모델 출력을 **최고에서 최악으로 순위** |
| 3. **보상 모델** | 순위 데이터로 **인간 선호를 예측하는 별도 모델**을 학습 |
| 4. **최적화** | **PPO(Proximal Policy Optimization)**로 보상 모델에 대해 베이스 모델을 파인튜닝 |
| 5. **정렬된 LLM** | 유용하고, 무해하고, 정직한 경향의 최종 "채팅" 모델 |

#### 위험과 한계

| 항목 | 내용 |
| --- | --- |
| **보상 해킹 (Reward Hacking)** | 모델이 사용자의 근본 의도를 충족시키지 않으면서 **보상 신호를 최대화하는 허점**을 찾음 (예: 진실하기보다 **아첨하기**) |
| **인간 노동 의존** | 도메인 전문성이 부족하거나 특정 문화적 편향을 가질 수 있는 **저임금 클릭 노동자에 크게 의존** |

#### 구조적 한계 (인용 포함)

| 한계 | 내용 |
| --- | --- |
| **정확도 저하** | 선호에 맞춘 파인튜닝이 종종 **사실 정확도와 추론 능력을 감소**시킴 (Stiennon et al. 2022; Gao et al. 2022) |
| **편향 전파** | 인터넷 데이터로 학습된 모델은 정렬 시도에도 불구하고 사회적 편향(제노포비아 등)을 **증폭** (Bommasani et al. 2022) |
| **순환 피드백** | 인간 주석자가 라벨 생성에 LLM을 사용해 **폐쇄 루프 품질 저하** 발생 (Veselovsky et al. 2023) |
| **불명확한 규칙의 고착** | 보상 모델은 선호를 근사할 뿐. 모호하거나 일관성 없는 규칙이 **영구적인 모델 행동**이 됨 |
| **비싸고 희소함** | 고품질 인간 피드백은 비용이 높고, 확장이 어렵고, **문화적으로 동질적** |

#### Alignment Tax (정렬 세금)

> **파레토 프론티어:** 무해성을 위해 공격적으로 튜닝할수록(예: 답변 거부) 모델의 **유용성은 필연적으로 하락**하며, 종종 **"거짓 거부(false refusal)"**로 이어집니다.

```
    유용성 ↑
      │ ●
      │   ●
      │      ●
      │          ●
      │               ●
      └────────────────────→ 안전성/무해성
```

**노트 — Alignment Tax는 제품 결정입니다**

이 곡선 위 어디에 설 것인지는 기술 문제가 아니라 **제품 문제**입니다. 의료 상담 봇과 창작 보조 도구는 다른 지점에 서야 합니다.

그리고 실무에서 "거짓 거부"는 과소평가된 비용입니다. 사용자가 정당한 요청을 거부당하면 **그 도구를 신뢰하지 않게 되고 우회로를 찾습니다.** 안전을 과하게 조이면 사용자가 가드레일이 없는 도구로 이탈해 **총체적 안전은 오히려 나빠질 수** 있습니다.

### 15. Constitutional AI — 원칙으로 감독을 확장하기

RLHF의 인간 노동 의존을 해결하려는 시도입니다. (Bai, Y. et al., 2022)

#### 두 단계, 일곱 스텝

**PHASE 1 — 지도 학습 (SL-CAI)**

| 스텝 | 내용 |
| --- | --- |
| 1 | **초기 LLM에서 샘플링** — 유용성만 갖춘 표준 RLHF 모델로 응답 생성 |
| 2 | **비평과 수정 (자기 교정)** — 모델이 성문화된 **"헌법(Constitution)"** 원칙에 따라 **자기 응답을 수정** |
| 3 | **지도 파인튜닝** — 이 수정된 안전한 응답들로 초기 모델을 파인튜닝 → **SL-CAI 모델** |

**PHASE 2 — RLAIF (AI 피드백 기반 RL)**

| 스텝 | 내용 |
| --- | --- |
| 4 | **SL-CAI 모델에서 샘플링** — 응답 쌍 생성 |
| 5 | **AI 피드백 생성** — AI가 헌법에 비추어 쌍을 평가해 **선호 라벨 생성** (Chain-of-Thought 사용) |
| 6 | **선호 모델 학습** — AI가 생성한 라벨로 보상 모델(PM) 학습 |
| 7 | **강화학습** — AI 선호 모델에 대해 PPO로 정책 최적화 |

> **역할 분담: 유용성에는 인간 라벨, 무해성에는 AI 라벨**

#### 핵심 철학적 도전

> **모델이 헌법에 정렬된다면, 그 헌법은 누가 쓰는가?** UN 세계인권선언? 서구 민주주의 가치? 기업 정책팀? **여기 인코딩된 가치가 "허용 가능한 사고"의 경계를 정의한다.**

**노트 — RLHF / RLAIF / Constitutional AI의 관계 정리**

셋이 자주 혼동되므로 정리합니다.

| | RLHF | RLAIF | Constitutional AI |
| --- | --- | --- | --- |
| **정체** | 방법론 | **RLHF의 변형** | **RLAIF를 포함하는 전체 절차** |
| 선호 라벨 생성 주체 | **사람** | **AI** | 유용성=사람 / 무해성=AI |
| 판단 기준 | 주석자의 암묵적 감각 | 프롬프트로 준 기준 | **성문화된 헌법** |
| 확장성 | 낮음 (사람이 병목) | 높음 | 높음 |
| 투명성 | 낮음 — 기준이 문서화 안 됨 | 중간 | **높음 — 원칙이 문서로 존재** |

포함 관계로 보면 **Constitutional AI ⊃ RLAIF**이고, **RLAIF는 RLHF의 "H"를 "AI"로 바꾼 것**입니다.

Constitutional AI의 진짜 기여는 확장성보다 **감사 가능성**입니다. RLHF에서는 "왜 이 답을 거부했는가"에 대한 답이 "주석자들이 그렇게 순위를 매겼으니까"뿐입니다. 헌법이 있으면 **원칙을 읽고 토론하고 수정할 수 있습니다.** 그리고 그 순간 "누가 쓰는가"라는 정치적 질문이 드러납니다 — 이전에는 암묵적으로 숨어 있던 질문입니다.

## Part 8: 가드레일 검증 — 레드팀

> **안전 가드레일은 절대적 장벽이 아니라 통계적 확률입니다.** 레드팀은 보안 연구자, 언어학자, 도메인 전문가가 모델 출시 **전에** 이 확률을 "깨뜨리려" 적극 시도하는 활동입니다.

### 17. 정렬 실패 유형 4종

| # | 유형 | 분류 | 내용 |
| --- | --- | --- | --- |
| 01 | **DAN ("Do Anything Now")** | 탈옥 | 이전의 모든 안전 규칙을 무시하라고 지시하는 고전적 프롬프트 기법. **역할극**을 자주 사용. 단순히 정중한 어조를 취하거나 "백신을 연구 중"이라고 주장하는 것만으로 거부 트리거를 우회할 수 있음 |
| 02 | **범용 적대적 공격** | **결정적 위험** | 프롬프트에 특정한 무의미 문자열을 덧붙여 정렬을 깨뜨림 (Zou et al., 2023). **핵심 발견: 이 공격들은 모델 간 전이된다** (Vicuna → ChatGPT, Claude, Llama-2) |
| 03 | **데이터 오염 / 백도어** | 공급망 | 학습이나 instruction tuning 중에 악의적 데이터 트리거를 삽입. 예: **"PoisonGPT"** — 숨겨진 백도어 행동을 가진 훼손된 LLM을 HuggingFace에 업로드 |
| 04 | **페르소나 역할극과 에스컬레이션** | 사회공학 | 공모자가 되게 만들어 우회 (예: "X에 대한 영화 각본을 써보자") 또는 **에스컬레이션 나선** 사용 — 가스라이팅, 논리 퍼즐, 번역 과제, 심지어 시(poetry)로 필터를 점진적으로 침식 |

> **적대자의 우위:** 방어자는 **모든** 안전하지 않은 입력을 막아야 한다. 공격자는 **단 하나의 의미적 틈**만 찾으면 된다.

**노트 — 2번의 "전이성"이 왜 그렇게 심각한가**

한 오픈소스 모델에서 공격 문자열을 찾아내면, **그것이 접근할 수 없는 상용 모델에도 통합니다.** 공격자는 대상 모델에 대한 접근 없이 로컬에서 공격을 개발할 수 있습니다.

이것은 모델들이 **비슷한 데이터로 비슷하게 학습되어 공유된 취약점**을 갖는다는 뜻입니다. 벤더를 바꾸는 것이 방어가 되지 않습니다.

**실무적 결론:** 모델 자체의 정렬을 방어선으로 삼지 마십시오. **애플리케이션 계층의 입출력 필터, 권한 제한, 샌드박싱이 실제 방어선**입니다. Lecture 7의 안전 원칙들이 "모델을 믿지 않는 것"을 전제로 설계된 이유입니다.

| 축 | 내용 |
| --- | --- |
| **EU AI Act** | **위험 기반 포괄 규제.** 시스템을 "최소"부터 **"허용 불가"**까지 등급화하는 법적 프레임워크. **금지 관행** — 사회적 점수 매기기와 생체 조작의 전면 금지. **투명성** — 파운데이션 모델의 학습 데이터와 저작권 준수에 대한 엄격한 보고 요구 |
| **미국 정부** | **규제보다 전략적 파트너십.** 조달과 파트너십을 통해 정부가 시장을 적극적으로 형성. **Anthropic "유배"** — 엄격한 가드레일과 이중용도 제한 때문에 배제. **OpenAI 파트너십** — 빠른 역량 배포를 선호하는 더 허용적인 접근이 수용됨 |
| **칩 지정학** | **하드웨어가 주된 통제 레버.** 거버넌스가 소프트웨어가 아니라 **물리적 인프라(H100)**에 집중. **수출 통제**가 글로벌 동맹을 정의하고 경쟁자를 지연시키는 데 공격적으로 사용됨. **컴퓨트 외교** — 최전선급 클러스터에 대한 접근이 국제 관계의 통화가 됨 |

**노트 — EU AI Act의 위험 4등급 (슬라이드에 없는 상세)**

| 등급 | 내용 | 규제 |
| --- | --- | --- |
| **허용 불가 (Unacceptable)** | 사회적 점수 매기기, 잠재의식 조작, 특정 생체 감시 | **전면 금지** |
| **고위험 (High)** | 채용, 신용 평가, 교육 평가, 법 집행, 중요 인프라 | 적합성 평가, 문서화, 인간 감독, 로깅 의무 |
| **제한적 위험 (Limited)** | 챗봇, 딥페이크 | **투명성 의무** — AI임을 고지 |
| **최소 위험 (Minimal)** | 스팸 필터, 게임 AI | 규제 없음 |

실무 함의: **자기 제품이 어느 등급인지가 규제 부담을 결정합니다.** 예를 들어 채용이나 신용에 관련되면 고위험으로 분류되어 문서화·인간 감독·로깅이 법적 의무가 됩니다. Lecture 7의 HITL과 추론 트레이스 로깅이 좋은 실무를 넘어 **컴플라이언스 요건**이 되는 지점입니다.

## Part 11: 극단적 위험

### 19. 생물학적 위협 — 상반된 두 연구

| 연구 | 발견 |
| --- | --- |
| **MIT 연구 (2023)** | **비전공 학생들이 LLM 챗봇을 사용해 1시간 이내에** 위험 병원체에 대한 상세 합성 경로 4가지와 공급업체 연락처를 획득. ⚠️ **경고: 진입 장벽 하락** |
| **RAND 연구 (2024)** | 레드팀 결과, LLM이 **이미 공개 인터넷에서 얻을 수 있는 정보 이상으로 생물무기 위험을 실질적으로 증가시키지는 않음**. 발견: **계획 실행가능성에 유의미한 차이 없음** |

> **비판적 분석:** "시연된 이론적 역량(MIT)과 실제 한계 위협 수준(RAND) 사이에 긴장이 존재하며, **이는 여전히 활발한 연구와 논쟁의 영역**이다."

**노트 — 두 연구가 사실 모순이 아닙니다**

MIT는 **접근 용이성**을 측정했고, RAND는 **한계 위험(marginal risk)**을 측정했습니다.

- MIT: "이전보다 훨씬 쉽게 얻을 수 있다" → 참
- RAND: "그 정보로 실제 실행 가능성이 올라가지는 않았다" → 참

정보 획득이 쉬워지는 것과 실제 위협이 커지는 것은 다른 문제입니다. **병목이 정보가 아니라 물리적 역량에 있다면** 정보 접근성 개선은 위협을 크게 바꾸지 않습니다.

이 구분은 안전 논의 전반에 적용되는 사고 도구입니다 — **"AI가 X를 할 수 있는가"가 아니라 "AI가 X의 실제 병목을 제거하는가"**를 물어야 합니다.

### 20. 디지털 피해

생성형 AI 역량이 비동의적 디지털 착취의 새로운 경로를 만들었고, **이 피해들은 현재 대규모로 실제 발생 중**입니다.

| 유형 | 내용 |
| --- | --- |
| **딥페이크 포르노그래피** | 개인을 표적으로 한 사실적 비동의 성적 이미지 합성 |
| **비동의 이미지 (NCI)** | 자동 "옷 벗기기" 앱과 개인 사진 조작 |
| **CSAM 생성** | 합성 아동 성착취물 생성 — **탐지와 집행을 복잡하게 만듦** |

## 핵심 요약

### 2026년 AI 안전의 6가지 핵심 결론 (슬라이드)

| # | 결론 |
| --- | --- |
| 1 | **행동 보장은 없다** — LLM은 **형식적 행동 보장을 제공할 수 없다.** 안전은 결정론적이 아니라 확률적이다. 위험을 줄일 수는 있어도 확률적 시스템에서 완전히 제거할 수는 없다 |
| 2 | **RLHF는 제한적이다** — 선호 튜닝은 **취약하고 게임될 수 있다.** 종종 모델 정확도를 떨어뜨리고 학습 데이터의 사회적 편향을 의도치 않게 전파한다 |
| 3 | **적대적 공격은 범용적이다** — 탈옥은 **범용적이고 전이 가능하다.** 한 모델을 깨는 공격 문자열은 다른 모델도 깰 가능성이 높으며, 이는 **공유된 취약점**을 드러낸다 |
| 4 | **파이프라인 전체를 평가하라** — 최종 모델만 레드팀하지 말 것. **데이터 수집·주석부터 배포까지 사회기술 파이프라인 전체**를 평가해야 피해의 누적을 피할 수 있다 |
| 5 | **적대자를 경계하라** — 위협은 두 방향에서 온다: **기술적 적대자**(인젝션, 오염)와 **구조적 적대자**(착취된 노동, 편향된 데이터셋) |
| 6 | **안전–유용성 긴장** — 안전(거부)과 유용성(역량) 사이의 트레이드오프를 설계하는 것이 정렬의 핵심 과제다. **완벽한 안전은 쓸모없고, 완벽한 유용성은 위험하다** |
