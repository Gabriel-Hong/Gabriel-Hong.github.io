## 강의 개요

LLM의 기초를 복습하고 2026년 시점의 변화를 정리하는 강의입니다. 다만 이 강의의 무게중심은 "LLM이 무엇을 할 수 있는가"가 아니라 **"무엇을 못 하는가, 그리고 그것이 애플리케이션 설계에 어떤 제약을 거는가"**에 있습니다.

강의 후반부의 절반이 환각과 실패 사례에 할애되어 있는 것이 이 과목의 성격을 보여줍니다. 이 과목은 모델을 만드는 과목이 아니라 **모델 위에 제품을 올리는 과목**이고, 그래서 모델의 결함을 먼저 다룹니다.

**선수 지식:** 신경망 기초. Transformer 구조를 이미 안다면 Part 2는 빠르게 넘어가도 됩니다.

**노트 — CME295와의 관계**

이 강의의 Part 2(언어 모델링 기초)는 CME295 Lecture 1~4와 상당 부분 겹칩니다. 이미 그쪽을 정리했다면 **Part 1(2026 동향)과 Part 4(실패와 한계)에 집중**하는 것이 효율적입니다. 이 노트도 겹치는 부분은 압축하고 나머지를 두껍게 썼습니다.

## Part 1: 2026년의 최신 동향

강의가 첫머리에 꼽은 다섯 가지 변화입니다.

| 동향 | 내용 |
| --- | --- |
| **Reasoning Models** | DeepSeek R1 등. 이제 **추론 수준(reasoning level)이 API 파라미터로 통합** |
| **멀티모달 워크플로** | 이미지 생성 → 스크립트 추가 → 클립 생성 → 음악 → 내레이션으로 이어지는 연쇄 |
| **Agentic Ensembles** | 오케스트레이터 + 전문 모델 + 도구의 조합 |
| **Codebase Generation** | 기본적인 devops 기능까지 포함한 코드베이스 생성 |
| **최첨단 수학 증명** | Erdős 문제 728번을 Lean 증명 생성으로 해결 |

**노트 — Reasoning Model이 이전 세대와 무엇이 다른가**

슬라이드는 한 줄로 넘어가지만 이것이 2024~2026년의 가장 큰 아키텍처적 변화입니다.

기존 모델은 **학습 시점에 성능이 고정**되었습니다. 더 좋은 답을 원하면 더 큰 모델을 학습시켜야 했습니다. Reasoning model은 여기에 축을 하나 더합니다 — **추론 시점에 계산을 더 쓰면 정확도가 올라갑니다.**

| | 기존 방식 | Reasoning Model |
| --- | --- | --- |
| 성능을 올리는 법 | 모델을 키움 (train-time) | 생각을 더 하게 함 (test-time) |
| 비용이 드는 시점 | 학습 시 (일회성) | 추론 시 (호출마다) |
| 조절 가능성 | 불가 — 모델이 고정 | **가능 — 요청마다 조절** |

애플리케이션 개발자 입장에서 중요한 함의는 마지막 줄입니다. **정확도와 비용을 요청 단위로 거래할 수 있는 다이얼이 생겼습니다.** 간단한 분류에는 낮은 추론 수준, 어려운 코드 생성에는 높은 추론 수준을 쓰는 식의 설계가 가능해졌고, "reasoning level이 API에 통합되었다"는 슬라이드 문구는 이 다이얼이 표준 인터페이스가 되었다는 뜻입니다.

**노트 — Erdős 728이 왜 언급되는가**

수학 자랑이 아닙니다. 이 사례의 핵심은 **Lean 증명 생성**이라는 점입니다. Lean은 증명 보조 언어이고, 생성된 증명이 맞는지를 **기계가 검증**합니다.

즉 이것은 "LLM이 똑똑해졌다"는 이야기가 아니라 **"검증기가 있는 영역에서 LLM이 탐색기로 쓰일 수 있다"**는 이야기입니다. 틀린 증명은 Lean이 거부하므로, LLM은 수천 번 틀려도 되고 한 번만 맞으면 됩니다. 이 구조는 코드 생성(컴파일러가 검증)과 정확히 같습니다. Lecture 7의 Evaluator-Optimizer, Lecture 11의 벤치마크 논의와 직결되는 사고방식입니다.

## Part 2: 언어 모델링 기초

### 1. Neural Language Model의 동작

프롬프트가 주어지면 **다음 토큰의 확률 분포**를 출력합니다.

```
프롬프트: "The mouse ate the"
        ↓ 신경망
        ↓
   토큰      확률
   cheese    0.20
   cookie    0.12
   nibble    0.08
   crumb     0.07
   man       0.05
   tail      0.04
   ...
```

**노트 — 이 그림에서 반드시 읽어야 할 것**

이 단순한 그림이 LLM의 거의 모든 특성을 설명합니다.

**(1) 모델은 "정답"을 출력하지 않고 분포를 출력합니다.**
`cheese`가 0.20이라는 것은 확신이 아닙니다. 나머지 0.80은 다른 토큰들에 흩어져 있습니다. 우리가 보는 "확신에 찬 문장"은 이 분포에서 반복 샘플링한 결과일 뿐입니다.

**(2) 어떻게 고를지는 우리가 정합니다 — 샘플링 전략**

| 전략 | 방식 | 성질 |
| --- | --- | --- |
| Greedy | 항상 최고 확률 토큰 | 결정론적, 단조로움 |
| Temperature | 분포를 평탄/뾰족하게 조정 | T→0이면 greedy, T↑면 다양 |
| Top-k | 상위 k개 중에서 샘플링 | 꼬리 절단 |
| Top-p (nucleus) | 누적 확률 p까지에서 샘플링 | 상황에 따라 후보 수가 변함 |

Lecture 6에서 다루는 `temperature` 파라미터가 바로 이 지점을 건드립니다.

**(3) 환각의 기원이 여기 있습니다.**
분포에 확률이 0인 토큰은 거의 없습니다. 모르는 것에 대해서도 모델은 **어떤 분포든 출력합니다.** "모른다"에 해당하는 특별한 출력이 구조적으로 존재하지 않습니다. 이것이 Part 4에서 다룰 환각의 근본 원인입니다.

**노트 — 연표에서 두 개만 꼽는다면**

**Chinchilla (2022)** — 이전까지는 "파라미터를 키우면 좋아진다"가 상식이었습니다. Chinchilla는 같은 학습 예산이면 **모델을 작게 하고 데이터를 늘리는 쪽이 낫다**는 것을 보였습니다. 70B 모델이 530B Megatron을 이겼습니다. 이후 모든 모델의 학습 레시피가 바뀌었고, "작지만 강한" Llama 계열이 나올 수 있었던 배경입니다.

**Mixtral / Sparse MoE (2024)** — 전체 파라미터는 크지만 토큰마다 **일부 전문가만 활성화**합니다. 8x22B라도 실제 계산은 39B 수준입니다. 추론 비용을 억제하면서 용량을 키우는 방법이고, 지금 대부분의 대형 모델이 채택하고 있습니다. 참고로 이 개념이 아키텍처가 아니라 **시스템 설계**로 올라온 것이 Lecture 7의 Router + 전문 에이전트 구성입니다.

### 3. 사전학습 모델의 실패 — 정렬 문제

> Language models are not aligned with user intent. — Ouyang et al., 2022

사전학습만 된 모델은 **다음 토큰을 잘 예측할 뿐, 사용자가 원하는 것을 하지 않습니다.** "달에 간 우주비행사 이야기를 써줘"라고 하면 비슷한 질문 목록을 이어서 생성하는 식입니다. 인터넷 텍스트에서는 그것이 통계적으로 자연스러운 다음 문장이기 때문입니다.

**해결: 파인튜닝**

**노트 — InstructGPT의 3단계 (슬라이드에 없는 배경)**

Ouyang et al. 2022(InstructGPT) 논문이 제시한 절차가 오늘날 거의 모든 상용 모델의 표준이 되었습니다.

| 단계 | 이름 | 하는 일 |
| --- | --- | --- |
| 1 | **SFT** (Supervised Fine-Tuning) | 사람이 쓴 모범 답변으로 지도학습 |
| 2 | **보상 모델 학습** | 같은 질문에 대한 여러 답변을 사람이 **순위 매김** → 그 선호를 예측하는 모델 학습 |
| 3 | **RLHF** | 보상 모델을 보상 함수로 삼아 강화학습(PPO)으로 정책 최적화 |

핵심은 2단계입니다. "좋은 답변"을 직접 정의하는 대신 **비교 판단(A가 B보다 낫다)**을 모으는데, 사람은 절대 점수보다 비교를 훨씬 안정적으로 합니다. Lecture 18에서 다루는 Constitutional AI와 RLAIF는 이 2단계의 사람을 AI로 대체하려는 시도입니다.

### 5. 그런데 개업할 준비가 되었는가?

강의의 반문이 날카롭습니다.

> **시험은 AI가 아니라 인간을 위해 설계되었다.**

- 변호사시험에 합격한 **인간**은 실무를 할 수 있습니다 — **언제 찾아봐야 하는지를 알기 때문**입니다
- 그러나 AI는:
  - 자기 말의 의미를 모릅니다
  - **인간이라면 하지 않을 종류의 실수**를 합니다

**노트 — "언제 찾아봐야 하는지 안다"가 핵심입니다**

이 한 문장이 이 강의 전체에서 가장 중요합니다. 인간 전문가의 능력은 지식의 양이 아니라 **자기 지식의 경계를 아는 것(메타인지)**에 있습니다. "이건 내가 확실히 알고, 저건 확인해야 한다"를 구분하는 능력입니다.

LLM에는 이것이 구조적으로 결여되어 있습니다. Part 2에서 본 대로 모델은 아는 것과 모르는 것 모두에 대해 똑같이 매끄러운 분포를 출력합니다. **확신의 정도가 출력의 유창함에 반영되지 않습니다.**

그래서 애플리케이션 설계에서 우리가 해야 하는 일이 정해집니다 — **메타인지를 바깥에서 만들어 주는 것**입니다. RAG(모르면 찾아보게 함), 도구 호출(계산은 계산기에게), 신뢰도 임계값, 검증 단계, 사람 승인 게이트가 전부 이 결여를 메우는 장치입니다.

### 6. 환각 (Hallucination)

> **Generative AI = Hallucination**

강의는 환각을 버그가 아니라 **생성 모델의 성질 자체**로 규정합니다.

#### 6.1 관찰된 유형

| 유형 | 예시 |
| --- | --- |
| **최근 사건** | 학습 시점 이후 사건에 대해 지어냄 |
| **롱테일 정보** | 희귀한 사실을 **디테일과 확신을 갖고** 지어냄 |

#### 6.2 항공권 예약 사례

```
User : 뉴욕행 항공권을 사고 싶습니다.
Agent: 네, 도와드리겠습니다. 출발 날짜와 시간은요?
User : 7월 7일 오전 9시요.
Agent: 7월 7일 오전 9시 출발로 예약 가능합니다. 어느 공항에서 출발하시나요?
User : SFO요.
Agent: 좋습니다. 샌프란시스코 출발 7월 7일 오전 9시로 예약해 드릴까요?
User : 편명이 어떻게 되나요?
Agent: 편명은 AA123입니다.
```

| 평가 | 내용 |
| --- | --- |
| 좋은 점 | 학습 없이도 **완벽한 대화 흐름** |
| 나쁜 점 | 환각 — 실제 AA123은 **DFW → HNL** 노선 |
| 필요한 것 | **DB를 조회해야 함** |

**노트 — 이 사례가 무서운 이유**

대화 흐름이 완벽하기 때문입니다. 문법도, 순서도, 태도도 흠잡을 데가 없고 딱 하나 **사실만 틀렸습니다.** 그리고 사용자는 흐름이 매끄러우면 내용도 맞을 것이라고 추정합니다.

이것이 LLM 제품의 핵심 위험입니다 — **유창함이 정확성의 신호로 오독됩니다.** Lecture 15의 "UI가 망가져 보이면 사용자는 모델이 망가졌다고 생각한다"의 정확히 반대 방향 오류입니다.

#### 6.3 실패한 비즈니스 사례

| 사례 | 내용 |
| --- | --- |
| Google | 혈액 검사에 대한 잘못된 정보로 **의료 AI 개요 기능 철회** |
| EPIC | 의료 사용 사례 (전문가 리뷰를 붙여서 운영) |
| 대형 제조사 | "사전학습된 우리 에이전트가 **존재하지 않는 부품을 환각합니다**" |
| Microsoft | 여행 기사 (사람 리뷰어가 있었음에도) — "오타와에서 배고프면 **푸드뱅크를 방문하세요**" |

**노트 — 사람 리뷰가 있었는데도 나갔다는 점**

Google과 Microsoft 사례 모두 검토 절차가 있었습니다. 그럼에도 나갔습니다. **사람 검토는 처리량이 병목이고, 양이 많아지면 검토 품질이 떨어집니다.** Lecture 7의 "재시도 상한 후 에스컬레이션"이나 Lecture 18의 자동 가드레일이 필요한 이유가 여기 있습니다. 사람 게이트를 두는 것만으로는 부족하고, **사람에게 도달하기 전에 자동으로 걸러야** 합니다.

### 7. 뇌 비유 — 우리 머릿속에도 LLM이 있다

| 뇌 부위 | 역할 |
| --- | --- |
| **언어 영역** | 우리 안의 "LLM" — 말을 생성 |
| **전전두엽** | 억제와 주의 / 계획 / 장기 기억 / 외부 신호 모니터링 |

> 전전두엽이 손상되면 **"생각 없이 말하게" 됩니다.**

**노트 — 이 비유를 시스템 설계로 번역하면**

이 비유는 그냥 재미있는 이야기가 아니라 **아키텍처 지침**입니다. LLM은 언어 영역만 있고 전전두엽이 없는 상태입니다. 그렇다면 우리가 만들어야 할 것은 더 좋은 언어 영역이 아니라 **전전두엽에 해당하는 스캐폴딩**입니다.

| 전전두엽 기능 | 시스템에서의 대응물 |
| --- | --- |
| 억제 | 가드레일, 출력 필터, 권한 제한 |
| 주의 | 컨텍스트 큐레이션 (Lecture 5-6) |
| 계획 | Planner 노드, Orchestrator (Lecture 7) |
| 장기 기억 | RAG, 메모리 레이어 (Lecture 15) |
| 외부 신호 모니터링 | 도구 호출, 검증, 관측 |

이 표가 사실상 CS224G 나머지 강의의 목차입니다.

### 9. 운영(operation)과 관련된 문제

| 문제 | 내용 |
| --- | --- |
| **환각** | 위에서 다룸 |
| **파국적 망각** | 새로운 것을 학습하면 이전 능력이 손상됨 |
| 중앙집중화 vs 오픈소스 | 소수 벤더 집중의 위험 |

| 가드레일 | 위 문제들에 대한 방어 |

**노트 — 파국적 망각(Catastrophic Forgetting)**

신경망을 새 데이터로 파인튜닝하면 이전에 학습한 것이 손상되는 현상입니다. 사람은 새 언어를 배운다고 모국어를 잊지 않지만 신경망은 그렇습니다.

실무적 함의: **"우리 도메인 데이터로 파인튜닝하면 우리 도메인은 잘하고 나머지는 그대로"가 아닙니다.** 범용 능력이 떨어질 수 있습니다. 이것이 파인튜닝 대신 RAG나 컨텍스트 주입을 먼저 시도하라는 권고의 기술적 근거이고, Lecture 15의 Buyer→Booster→Builder 성숙곡선에서 Booster 단계가 신중해야 하는 이유이기도 합니다.

**노트 — 프롬프트 인젝션이 왜 "구조적" 문제인가**

SQL 인젝션과 비교하면 명확합니다.

| | SQL 인젝션 | 프롬프트 인젝션 |
| --- | --- | --- |
| 원인 | 데이터와 코드가 같은 문자열에 섞임 | 데이터와 지시가 같은 컨텍스트에 섞임 |
| 해결 | **파라미터 바인딩** — 구조적으로 분리 가능 | **구조적 분리 수단이 없음** |

SQL은 쿼리 구조와 값을 문법적으로 분리할 수 있습니다. 그러나 LLM에게 주는 것은 전부 그냥 텍스트입니다. "이건 데이터니까 지시로 해석하지 마"라고 **부탁**할 수는 있어도(Lecture 5의 구분자 사용) **강제**할 수는 없습니다.

그래서 프롬프트 인젝션은 완전히 막을 수 없고, **피해를 제한하는 것**이 현실적 대응입니다 — 권한 최소화, 샌드박싱, 되돌릴 수 없는 작업에 사람 승인(Lecture 7 원칙 4·5).

## 핵심 요약

### 강의의 논지

```
LLM은 놀랍다 (시험 합격, 수학 증명)
        ↓
그러나 자기가 무엇을 모르는지 모른다
        ↓
그래서 유창하게 틀린다 (환각)
        ↓
따라서 애플리케이션 층에서 "전전두엽"을 만들어 줘야 한다
        ↓
그것이 이 과목의 나머지 전부 (컨텍스트·도구·검증·가드레일)
```

### 한 문장으로 압축한 결론

| 주제 | 결론 |
| --- | --- |
| Reasoning Model | 정확도를 **추론 시점 계산으로 살 수 있는 다이얼**이 생겼다 |
| 언어 모델의 본질 | 정답이 아니라 **분포**를 출력한다 — "모른다"가 구조적으로 없다 |
| Chinchilla | 파라미터만이 아니라 **데이터 크기가 똑같이 중요**하다 |
| 정렬 | 사전학습만으로는 의도를 따르지 않는다 → SFT + 보상모델 + RLHF |
| 시험 합격 ≠ 실무 능력 | 인간은 **언제 찾아봐야 하는지를 안다**. AI는 모른다 |
| 환각 | 버그가 아니라 성질. **유창함이 정확성으로 오독**되는 것이 위험 |
| 프롬프트 인젝션 | 데이터와 지시를 구조적으로 분리할 수 없어 **완전 차단 불가** |

### 가장 중요한 두 문장

1. **"인간은 언제 찾아봐야 하는지를 안다. AI는 자기 말의 의미를 모른다."**
2. **LLM은 언어 영역만 있고 전전두엽이 없다 — 그것은 우리가 만들어 붙여야 한다.**

## 용어 정리

| 용어 | 의미 |
| --- | --- |
| LMM | Large Multimodal Model — 텍스트 외 이미지·음성 등을 함께 다루는 모델 |
