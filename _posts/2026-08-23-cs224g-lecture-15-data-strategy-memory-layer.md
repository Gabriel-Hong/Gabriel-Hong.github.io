## 강의 개요

이 강의는 기술 강의가 아니라 **전략 강의**입니다. 다만 그 전략이 곧 아키텍처 결정으로 이어지기 때문에 엔지니어에게도 중요합니다.

**핵심 명제:**

> AI에서 승리하는 쪽은 **고도로 관련성 높고, 차별화되고, 품질 높은 데이터에 지속적으로 접근**할 수 있는 조직이다.
>
> 모든 공개 데이터가 파운데이션 모델에 흡수된 세상에서, **고유한 데이터가 가장 결정적인 전략 자산**이 된다.

## Part 1: 데이터가 진짜 경쟁 우위다

세 가지 전략 축을 제시합니다.

| 축 | 내용 |
| --- | --- |
| **Longitudinal Engagement** (종단적 참여) | **정적 데이터셋은 상품(commodity)이다.** 깊은 사용자 참여를 통해 **시간이 지날수록 더 나은 데이터를 벌어들이는** 제품을 만들어야 한다 |
| **Data Access Strategy** | 데이터 접근 경로를 **핵심 제품 기능으로** 다뤄라. 독점적 신호가 자연스럽게 생성되는 워크플로를 설계하라 |
| **Memory Layers** | 사용 데이터를 **복리로 쌓이는 우위**로 전환한다. 메모리 레이어가 범용 모델이 흉내 낼 수 없는 개인화된 에이전트 행동을 가능하게 한다 |

**노트 — "정적 데이터셋은 상품이다"의 무게**

이 문장이 이 강의 전체를 압축합니다. 한 번 사 온 데이터셋은 경쟁자도 살 수 있습니다. 방어선이 아닙니다.

방어 가능한 것은 **제품이 돌아가는 동안 계속 생성되는 데이터**입니다. 그래서 데이터 전략은 데이터 수집 계획이 아니라 **제품 설계 문제**가 됩니다. 이 강의가 계속 UI와 사용자 경험을 이야기하는 이유입니다.

## Part 2: 6가지 우위의 원천

Berkeley Research(2024)의 현대 AI 경쟁 우위 프레임워크입니다. 지속 가능한 해자를 만들려면 이 여섯 영역에서 뛰어나야 합니다.

| # | 원천 | 내용 |
| --- | --- | --- |
| 1 | **Differentiation of Data** | 범용 모델에 없는 독점적·산업 특화 데이터셋. **고유 가치의 기반** |
| 2 | **Strength of Digital Core** | **Buyer(API 사용자) → Booster(파인튜너) → Builder(커스텀 아키텍처)**로의 이동 |
| 3 | **Rate of Learning** | 조직의 적응 속도와 모델 개선 루프. 지속적 재학습 주기 |
| 4 | **Capability Reinvention** | 작업을 자동화하는 게 아니라 **엔드투엔드 워크플로를 재구상**. 근본적 프로세스 변화 |
| 5 | **External Partnerships** | 생태계 접근. 최고 수준의 도구·데이터 파트너 통합. **혼자 만드는 사람은 없다** |
| 6 | **Level of Trust** | 책임 있는 AI 관행, 안전 가드레일, 투명성. **엔터프라이즈 채택에 결정적** |

> **전략적 영향:** 여섯 영역 모두에서 강한 기업은 2023년 **주주총수익률(TRS)이 10.7%p 높았습니다.**

**노트 — 4번이 가장 어렵고 가장 중요합니다**

"작업 자동화"와 "워크플로 재구상"의 차이입니다.

- **자동화**: 기존 절차의 한 단계를 AI로 대체 → 그 단계만큼만 빨라짐
- **재구상**: 절차 자체가 달라짐 → 단계가 사라지거나 순서가 바뀜

전자는 경쟁자도 쉽게 따라 합니다. 후자는 조직 구조와 제품이 함께 바뀌어야 하므로 모방이 어렵습니다. 그리고 후자에서만 **새로운 종류의 데이터**가 생깁니다.

## Part 4: 데이터는 석유가 아니다

"데이터는 새로운 석유"라는 비유가 현대 AI 시대에 왜 깨지는가.

| | 상품적 관점 (옛 모델) | 전략적 관점 (새로운 현실) |
| --- | --- | --- |
| 성질 | **대체 가능·범용** — 석유 한 배럴은 어디서나 같음 | **차별적·맥락적** — 가치가 고유성과 특정 문제에 대한 관련성에 전적으로 달림 |
| 승리 조건 | **양이 이긴다** — 얼마나 많이 추출했는가 | **품질과 큐레이션이 이긴다** — **전문가 라벨 1,000개 > 노이즈 데이터 100만 개** |
| 시간 | **정적 가치** — 누가 언제 쓰든 변하지 않음 | **시간 민감·살아 있음** — 데이터는 부패한다. **피드백 루프를 통한 지속적 갱신이 필수** |
| 한 줄 | "데이터는 캐내야 할 원재료다" | **"데이터는 길러야 할 전문 인재다"** |

## Part 5: Buyer → Booster → Builder

AI 데이터 전략의 성숙 곡선입니다.

| 단계 | 차별화 | 내용 | 특징 | 예시 |
| --- | --- | --- | --- | --- |
| **1. Buyer** | 낮음 | API로 기성 모델 사용 (OpenAI, Anthropic) | 빠른 시장 진입 / 상품화된 역량 / **독점적 우위 0** | — |
| **2. Booster** | 중간 | RAG나 파인튜닝으로 독점 데이터 통합 | 맥락 인식 응답 / 도메인 성능 향상 / **데이터 접근으로 방어 가능** | Microsoft LLaVa-Med — 생의학 영상용으로 **하루 만에** 파인튜닝 |
| **3. Builder** | 최대 | 독점 데이터 파이프라인 위에 커스텀 모델·아키텍처 구축 | 가중치·편향에 대한 완전한 통제 / 고유 역량 / **넘기 가장 어려운 해자** | BloombergGPT(50B 금융 모델), Pfizer VOX(내부 생성형 발견 플랫폼) |

**노트 — 대부분의 조직에게 정답은 Booster입니다**

Builder가 좋아 보이지만 자체 모델 학습은 비용·인력·시간이 크고, Lecture 3에서 본 **파국적 망각** 문제도 안고 갑니다.

실제 승부처는 **Booster를 얼마나 잘 하느냐**입니다. 그리고 Booster 안에서도 파인튜닝보다 **RAG와 컨텍스트 설계가 먼저**입니다 — 되돌리기 쉽고, 데이터가 바뀌면 즉시 반영되며, 왜 그런 답이 나왔는지 추적 가능합니다.

## Part 6: 제품 인게이지먼트 — 데이터 전략의 핵심

### 전략 원칙

| 원칙 | 내용 |
| --- | --- |
| **사람들이 사랑하는 것을 만들어라** | **참여가 통찰에 선행한다.** 아무도 쓰지 않는 제품에서는 고품질 데이터를 모을 수 없다. 유용성이 데이터 엔진을 돌린다 |
| **종단적 > 거래적** | 일회성 체험은 노이즈다. 방어 가능한 데이터셋은 **시간에 걸친 지속적 사용 패턴**에서 나온다 (리텐션 = 데이터 깊이) |

> **"아무도 쓰지 않는 제품의 완벽한 데이터 전략은, 인기 있는 제품의 무전략보다 나쁘다."**

### 구체적 행동

| 행동 | 내용 |
| --- | --- |
| **깊은 지표를 계측하라** | DAU만 추적하지 말 것. **기능 채택 깊이, 세션 길이, 특정 도구의 반복 사용**을 측정 |
| **참여를 데이터 가치에 연결하라** | 사용자 활동과 **확보된 독점 데이터의 양·품질**을 직접 상관시키는 대시보드를 만들 것 |

> **목표: 사용(usage)을 독점 자산으로 전환하는 것.**

## Part 8: 사용자 피드백 기법 6종

| 기법 | 내용 | 예시 |
| --- | --- | --- |
| **Label Feedback** | 출력을 사전 정의된 클래스로 분류. 분류 과제에 **고신호·저노력** | "이것은 A(좋음), B(나쁨), C(둘 다 아님) 중 무엇인가?" |
| **Discrete Feedback** | 단순 평점이나 이진 선택. 사용자에게 가장 쉽고, 총계 품질 지표에 최적 | 👍/👎, 별 1~5개 |
| **Explanations** | 평점의 "왜"를 묻기. **모델 추론 실패에 대한 깊은 통찰** 확보 | "왜 이 응답을 1점으로 매기셨나요?" |
| **Qualitative Feedback** | 자유 텍스트. 파싱은 어렵지만 **새 기능·버그의 가장 풍부한 원천** | "경험을 알려주세요" 텍스트 박스 |
| **Passive Learning** | 행동에서 선호를 추론. **마찰 0**이지만 의도 해석에 주의 필요 | 체류 시간, 클릭스트림, 재생성 요청 |
| **AI Overrides** ⭐ | 사용자가 AI 출력을 직접 편집. **그 "diff"가 완벽한 학습 라벨이 된다** | 사용자가 생성된 이메일 초안을 보내기 전에 수정 |

**노트 — AI Overrides가 왜 특별히 강력한가**

여섯 중 마지막이 압도적으로 가치가 높습니다. 이유가 셋 있습니다.

**(1) 마찰이 0입니다.** 사용자는 피드백을 주려고 수정하는 게 아니라 **자기 일을 하려고** 수정합니다. 별점을 매기는 것과 달리 추가 노력이 없습니다.

**(2) 신호가 정확합니다.** "3점"은 무엇이 문제인지 모릅니다. diff는 **정확히 무엇을 어떻게 바꿔야 했는지**를 말합니다. 문장 하나가 아니라 위치와 방향이 모두 담긴 라벨입니다.

**(3) 정답이 함께 옵니다.** 다른 피드백은 "틀렸다"만 알려주지만, override는 **"이게 맞다"**를 알려줍니다. 지도학습에 바로 쓸 수 있는 (입력, 정답) 쌍입니다.

실무 함의: **에이전트 시스템을 만든다면 사람 검토 게이트에서 "승인/거부"만 받지 말고 사용자가 직접 고친 내용을 반드시 저장하십시오.** 거부 사유보다 수정 diff가 훨씬 값집니다.

## Part 9: LLM으로 피드백 품질을 개선하기

| 기법 | 내용 |
| --- | --- |
| **자연스러운 후속 질문** | 모호한 피드백을 즉시 명확화하는 에이전트 배치. "2점을 주셨는데 — 톤 때문인가요, 정확성 때문인가요?"가 정적 폼이 놓치는 뉘앙스를 포착 |
| **통찰 요약** | 수천 개의 비정형 코멘트를 실행 가능한 테마로 전환. LLM은 자유 텍스트 피드백을 **우선순위가 매겨진 제품 로드맵으로 클러스터링**하는 데 뛰어남 |
| **근거를 메모리로 추출** | 사용자가 **왜** 수정했는지를 파싱해 **의미 메모리 레이어에 저장.** 상호작용마다 개인화가 개선됨 |
| **비정형 → 정형** | 지저분한 정성적 불만을 깔끔하고 라벨링된 데이터셋으로 변환 (범주 태그, 감성 점수, 기능 요청) |

> **목표: "무엇"이 아니라 "왜"를 이해하는 것.**

### 변환 예시

```
[원시 사용자 입력]
"목록으로 달라고 했는데 긴 문단으로 만드는 게 싫어요.
 빠르게 훑어볼 수가 없잖아요."
              ↓ LLM 처리
[부정 감성] [형식 문제] [선호: 목록]
              ↓
[구조화된 메모리 갱신]
{
  "user_preference": "concise_formatting",
  "preferred_structure": "bullet_points",
  "avoid": "dense_paragraphs"
}
```

**노트 — 이것이 "메모리 레이어"의 실제 모습입니다**

강의 제목의 "Memory Layer"가 추상적으로 들리지만 실체는 이 JSON입니다. 비정형 불만 → 구조화된 선호 → **다음 요청의 시스템 프롬프트에 주입**.

Lecture 5-6의 "Injected Knowledge — 보존된 메모리"가 어떻게 채워지는지를 보여주는 것이 이 슬라이드입니다. 두 강의를 이어 보면 **메모리 레이어 = 피드백 파이프라인의 출력물**이라는 구조가 보입니다.

## Part 10: 데이터 플라이휠 효과

```
1. 사용자가 기여        (암묵적·명시적 데이터 기여)
        ↓
2. 모델이 개선          (정확도·개인화 향상)
        ↓
3. 더 나은 UX           (더 많은 사용자를 끌어들임)
        ↓
4. 사용량 증가          (다양하고 종단적인 데이터 생성)
        ↓
5. 해자가 복리로 쌓임    (시간이 갈수록 복제 불가)
        ↓
      (1로 순환)
```

### 실제 사례

| 사례 | 플라이휠 |
| --- | --- |
| **Tesla Autopilot** | 주행 1마일 = 엣지 케이스 데이터 → Autopilot 개선 → 차량 판매 증가 → 더 많은 데이터 |
| **Grammarly** | 사용자가 교정을 수락 → 모델이 선호를 학습 → 제안 개선 → 리텐션 증가 |
| **Harvey AI** | 법률 문서 처리 → 법률적 뉘앙스 학습 → 신뢰 상승 → 더 많은 로펌 합류 |

> **성공에는 단순한 데이터 추출이 아니라 즉각적인 사용자 가치가 필요하다.**

**노트 — 플라이휠이 멈추는 조건**

강의는 도는 조건을 말하지만 멈추는 조건도 알아 둘 만합니다.

| 멈추는 지점 | 증상 |
| --- | --- |
| 1→2가 끊김 | 데이터는 쌓이는데 **모델에 반영하는 파이프라인이 없음** (가장 흔함) |
| 2→3이 끊김 | 모델은 좋아졌는데 **사용자가 체감하지 못함** |
| 3→4가 끊김 | 신규 유입은 있으나 **리텐션이 없어 종단 데이터가 안 쌓임** |
| 데이터 부패 | 도메인이 바뀌었는데 **과거 데이터로 계속 학습** |

첫 줄이 실무에서 압도적으로 흔합니다. 로그는 수집하는데 그것을 학습·평가에 쓰는 경로가 없으면 플라이휠이 아니라 **그냥 창고**입니다.

## Part 11: 내부 도구는 제품 승수다

## Part 14: 데이터 품질 — 모든 사용자가 같지 않다

| 원칙 | 내용 |
| --- | --- |
| **전문가 > 초보자** | 전문가(의사, 시니어 엔지니어)의 데이터에는 초보자가 놓치는 뉘앙스가 있다. **전문가 라벨 1,000개가 노이즈 크라우드소싱 10만 개를 이긴다** |
| **종단적 가치** | 유지된 사용자의 데이터는 **의도의 진화**를 드러낸다. 사용자가 시간에 따라 어떻게 변하는지가 개인화 메모리 레이어에 결정적 |
| **기여 가중치** | 손실 함수에서 모든 데이터를 동등하게 다루지 말 것. **기여자의 입증된 정확도와 평판으로 학습 샘플에 가중치**를 줄 것 |

### 고가치 사용자를 식별하는 법

| 방법 | 내용 |
| --- | --- |
| **교차 검증** | 누가 "어려운" 케이스를 맞히는가? |
| **메타데이터 분석** | 역할, 근속, 자격 검증 |
| **일관성 점수** | 유사 과제 반복 시의 분산 |
| **동료 일치도** | 다른 고평판 사용자와의 합의 |

**계층:** 초보/산발적(높은 양, 낮은 정확도) → 일관된 사용자(신뢰할 만한 종단 패턴) → **전문가(고신호 도메인 지식)**

**노트 — 가중치를 어떻게 실제로 적용하는가**

슬라이드가 "손실 함수에서 가중치를 주라"고 하지만, 학습을 하지 않는 대부분의 팀에게도 적용됩니다.

| 학습을 한다면 | 학습을 안 한다면 |
| --- | --- |
| 샘플별 loss weight | **평가 골든셋을 전문가 데이터로만 구성** |
| 저품질 샘플 제외 | few-shot 예시를 전문가 사례에서 선별 |
| 평판 기반 샘플링 | 충돌하는 피드백이 있을 때 **전문가 판단을 우선** |

핵심은 같습니다 — **모든 피드백을 평등하게 취급하면 다수의 평범한 판단이 소수의 정확한 판단을 덮어씁니다.**

**노트 — ACI가 무엇인가**

**Agent-Computer Interface**의 약자입니다. HCI(Human-Computer Interface)에 대응하는 개념으로, **도구가 에이전트에게 어떻게 보이는가**를 가리킵니다.

Lecture 7의 "docstring이 곧 프롬프트다"가 ACI 설계의 핵심입니다. 사람용 API 문서를 쓰듯이 **에이전트용 도구 설명에도 같은 수준의 설계 노력**을 들이라는 주장입니다.

## 핵심 요약

### 강의의 논지

```
모든 공개 데이터는 파운데이션 모델에 흡수되었다
        ↓
따라서 고유 데이터만이 남는 차별점이다
        ↓
그런데 정적 데이터셋은 상품이다 (사면 경쟁자도 산다)
        ↓
방어 가능한 것은 제품이 돌아가며 계속 생성되는 데이터다
        ↓
그러므로 데이터 전략 = 제품 설계 문제
        ↓
피드백을 사용에 내재화하고 플라이휠을 돌려라
```

### 한 문장으로 압축

| 주제 | 결론 |
| --- | --- |
| 데이터의 본질 | **석유가 아니라 길러야 할 인재.** 부패하므로 지속 갱신 필요 |
| 정적 데이터셋 | **상품이다.** 해자가 아니다 |
| 성숙 곡선 | Buyer → **Booster** → Builder. 대부분의 정답은 Booster |
| 참여 | **참여가 통찰에 선행한다.** 안 쓰는 제품엔 데이터가 없다 |
| 최고의 피드백 | **AI Overrides** — 사용자가 고친 diff가 완벽한 라벨 |
| 메모리 레이어 | 비정형 피드백 → 구조화된 선호 JSON → 다음 컨텍스트에 주입 |
| 플라이휠 | 가장 흔한 고장은 **데이터→모델 반영 경로 부재** |
| 내부 도구 | **공장 바닥이다.** Redcoat AI는 엔지니어링의 50%를 투입 |
| 데이터 품질 | **전문가 1,000 > 노이즈 100,000.** 기여자 평판으로 가중치 |
| 다양성 | 베타 사용자 ≠ 목표 시장 (UnifyID 95% 남성 기술직 실패) |
| 최종 판정 기준 | **"GPT-5가 지울 수 있으면 해자가 아니었다"** |

### 가장 중요한 세 문장

1. **"아무도 쓰지 않는 제품의 완벽한 데이터 전략은, 인기 있는 제품의 무전략보다 나쁘다."**
2. **AI Overrides — 사용자가 편집한 diff가 완벽한 학습 라벨이 된다.**
3. **"GPT-5가 당신의 우위를 지워버린다면, 그건 애초에 해자가 아니었다."**
